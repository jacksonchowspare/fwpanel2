## 一、「系统」tab 内容

1. **本机信息**（只读）：发行版、内核、CPU 核数、内存/swap、磁盘用量、负载、运行时长、主机名、时区
2. **内存与 Swap**：swap 创建（512M/1G/2G/4G/自定义）、调整、删除；`vm.swappiness` 可调；内存/swap 实时用量
3. **DNS**：当前解析方式与解析器、修改（自动适配 systemd-resolved / NetworkManager / 直接 resolv.conf）、
   搜索域、解析测试、失败自动回滚、一键还原上次备份
4. **时间与时区**：当前时区/时间/同步状态、设置时区、NTP 自动同步开关
5. **主机名**：查看/修改（含 `/etc/hosts` 同步）
6. **网络优化**：BBR 一键开启/关闭 + 内核版本；IPv6 优先策略（IPv4 优先 / 禁用 / 开启）
   —— 后两项从防火墙页**搬过来**
7. **面板端口**：从 SSH 安全页**搬过来**（面板自身设置）

**留在防火墙页**：服务快捷开关、一键开放端口/删除、规则管理（本质是端口放行操作，跟规则放一起最顺手）

## 二、接口设计（全部走鉴权 + 长任务 + 审计日志）

```
GET  /api/system                  总览（本机信息 + swap + dns + time + hostname + bbr + ipv6 + panel_port）
POST /api/system/swap             {size_mb} | {action:"resize",size_mb} | {action:"off"}   → 长任务
POST /api/system/swappiness       {value:0-100}
GET  /api/system/dns              当前解析配置（方式/解析器/搜索域）
POST /api/system/dns              {servers:[], search:[]} → 备份 → 写入 → 解析测试 → 失败回滚
POST /api/system/dns/restore      还原上次备份
GET  /api/system/dns/test         解析测试（多个域名 + 延迟）
POST /api/system/timezone         {tz} / {action:"ntp", enable:bool}
POST /api/system/hostname         {name}
POST /api/system/bbr              {enable:bool}      （复用现有 toggleBbr 逻辑，端点迁到此处）
POST /api/system/ipv6             {mode:v4_first|disable|enable}   （复用现有 setIpv6 逻辑）
POST /api/system/panel-port       {port}             （复用现有面板端口逻辑，端点迁到此处）
```

## 三、安全设计（主机级改动统一套路）

- **改前备份**：`/etc/fstab`、`/etc/resolv.conf`、`/etc/systemd/resolved.conf`、`/etc/timezone` → 备份到 `/etc/fwpanel/backups/<文件>.<时间戳>`
- **执行后立刻验证**：swap → `swapon --show` + `free -m`；DNS → 真实解析测试；时区 → `timedatectl`；主机名 → `hostname`
- **失败自动回滚**并回报原因；DNS 额外提供「还原上次备份」
- **长任务**：swap 创建/调整、DNS 变更（可能触发 resolved 重启）走 `start_task` + 进度上报（v3.1.1 已具备）
- **环境适配**：btrfs 上 swapfile 需特殊处理 → 明确提示不支持；容器内无 swap 权限 → 报错说明；
  DNS 管理方式探测顺序：systemd-resolved → NetworkManager → netplan → 直接写 resolv.conf（并提示可能被 cloud-init 覆盖）
- **幂等**：`/etc/fstab` 写入前检查是否已有该行；重复开启 BBR 不重复写 sysctl

## 四、分任务

### 后端
- A1 `system_info()`：发行版/内核/CPU/内存/swap/磁盘/负载/运行时长/主机名/时区（读 /proc、/etc/os-release、shutil.disk_usage）
- A2 swap：`swap_status()`、`swap_create(size)`、`swap_resize(size)`、`swap_off(purge)` + fstab 幂等写入 + 验证/回滚
- A3 swappiness：读写 `/etc/sysctl.d/99-fwpanel-swap.conf` + 立即生效
- A4 DNS：`dns_status()`（管理方式探测）、`dns_apply(servers, search)`（备份+写入+测试+回滚）、`dns_restore()`、`dns_test()`
- A5 时间：`time_status()`、`set_timezone(tz)`、`set_ntp(enable)`
- A6 主机名：`set_hostname(name)`（hostnamectl + /etc/hosts）
- A7 接口路由 + 长任务接线
- A8 单测：swap 参数校验/幂等 fstab/磁盘不足拒绝、DNS 探测与回滚、时区校验、主机名校验、BBR/IPv6 端点迁移后行为不变

### 前端
- B1 新 tab「系统」+ 7 张卡片（含"本机信息"总览）
- B2 从防火墙页移除 BBR/IPv6 两个区块；从 SSH 安全页移除面板端口区块（接口不变，仅搬家）
- B3 swap 卡片：档位 + 自定义 + 调整/删除 + 实时用量 + swappiness 滑块
- B4 DNS 卡片：当前配置 + 常用公共 DNS 快选（阿里/腾讯/Google/Cloudflare）+ 搜索域 + 测试/还原按钮
- B5 时间卡片、主机名卡片
- B6 主题一致性：沿用现有变量与组件，不新增静态资源

## 五、风险

1. DNS 改错会导致证书签发/apt/域名解析失效（面板经 IP 不受影响）→ 必须有测试与回滚，已设计
2. swap 调整时 `swapoff` 若内存紧张会卡住 → 先检查可用内存是否 ≥ swap 用量，不满足则拒绝并说明
3. 不同发行版差异（resolved/netplan/NetworkManager）→ 探测优先，探测不到时退化为写 resolv.conf 并提示
4. 搬家后老用户习惯变化 → 在两个原位置各留一行"该设置已移至「系统」页"的提示（一次性，可后续移除）
